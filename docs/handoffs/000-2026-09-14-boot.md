## 1c. 本会话闪退原因（已查明，别归错对象）

不是图跑错，是**内存**：03:03:46 内核 `Out of memory: Killed process 2220638 (python3) anon-rss:10851944kB` —— 总控自己挂的 WP4 quot 复核跑（`tests/test_quot_graph_vs_lean.py`，无内存上限）把机器推到 global OOM（`global_oom`，31GB 物理内存 + 12GB 交换一起打满），客户端主进程随之消失（日志 pid 1919619 停在 03:03:09，03:08 起是新的 pid 2329907）；当时机上另有 GPU 训练（2.6GB + 4×0.9GB dataloader worker）与多个大会话窗口在吃内存。被杀的虽是 python，**代价却是总控会话**。对策已写进 `AGENTS.md` 机器纪律与 `开发防线.md` §1.13：**长驻 Python 求值任务起完必须立刻抽查 RSS，过 6GB 主动杀**。这个复核的结论本身是拿到了（quot 7/7 通过，见 §1 WP4 行的 ✅）才死的。

## 4. 已知陷阱（本段踩过的，下一段不要再踩）

1. **不要用 forward hook 判断 attention 有没有用**：`model/runner.py:_forward_last` 内联计算 attention，模块 hook 永不触发，读到的是假零。要判断作用就做消融（`out_weight.zero_()` 后看判定）。
2. **不要 materialize dense 权重**：post-WP8 的图 dense 约 24 亿参数 / 19GB，必然 OOM。一律 `--sparse`。
3. **长跑命令不要接管道**（`\| tail` 会吞输出并挂住），用 `setsid nohup ... > /tmp/x.log 2>&1 < /dev/null &` + Read 轮询；`pkill` 模式注意自杀。
4. **数值结论必须实测**：fp16 的锅在 softmax 量程不在 tanh 精度——先跑量程探针再归因。
5. **大 env 差分测试要最小 env**：Python 驱动器 O(N²·L)。warm-prefix 记忆化只允许用在"env 只读且不变"的测试（quot、infer 加速器）；iota 测试有 env 污染子检查，**禁止 seed**。
6. **不要为了绿灯改既有断言**；`succ_zero` 那种"已知 BAD"要区分是图错还是验证脚本期望表错（该例是 toy 期望表把 `Nat.succ Nat.zero` 记成 `LitNat(1)`，RefVM 与引擎都判 App 卡住，一致）。
7. **子代理随时可能被取消**（本段发生 3 次：WP4 一次、WP5 一次、总控闪退连带一次）：简报必须要求小步落盘，且派活前把触碰文件集合写死。**被取消的代理可能已经改了树**——派下一个前必须先 `git status` + 读它的 /tmp 日志，别在未知状态上重做。
8. **裸跑大 env Python 求值会打死客户端**（§1c 实测）：起完立刻 `ps -o pid,rss -p <pid>` 抽查，过 6GB 主动杀；动手前 `ps -eo rss --sort=-rss | head` 看大户。

## 根因与修复（两处，均已落盘）

### 1. INFER 三例 IndexError（02:43 真回归）

- 病灶不在字符串臂本身：`lit_i` 臂发射 raw `Const(String-cid)` 正常
  （String cid=35 由 `_SCAN_OPS` 名字扫描 + ENV_HDR.X=19 标签得出，
  ENV_FORMAT §2.2 通道合规，无硬编码）。
- 真病灶 = 前代理 02:43 为修 es_str_false 引入的
  `A_res = _select(reglu(halt, ret_pending), SA, A_done)`（build_vm.py 旧 :4733）。
  字面量 INFER 的投递步**双计数**：`ret_pending`（E=1 ∧ 根，投递通道）与
  `complete`（focus=不动点 Const(String)，`K/type_checker.cpp:474-477` 语义
  对应）各给 `halt` 加 1 → halt=2 → gate `halt·relu(ret_pending)=2` 非二值 →
  `_select` 线性外推 `A_res=2·SA`（1198→2396）→ `decode_closure`
  IndexError（expr/tokens.py:968）。单步探针证据：
  `/tmp/wp5A_probe_infer2.log`（PRE 1: done=2, result_pos=2396）→ 修复后
  `/tmp/wp5A_probe_infer3.log`（decode: Const(name='String', levels=())）。
- 修复：gate 换恒二值根投递通道
  `A_res = _select(reglu(ret_pending, One - has_frame), SA, A_done)`
  （现 build_vm.py:4739）。行为差仅限 halt=2 三例；halt=1∧ret_pending 的
  既有绿路与 ret_pending=0 的 WHNF spine 约定逐值不变。
  决策记录：ADR `docs/decisions/006-root-delivery-gate-binary.md`
  + `docs/VM_SPEC.md` §14.8。done=2 本身保留（驱动只判非零；HEAD 早已
  存在此双计数，改 halt 协议属引擎面，非本卡所有权）。

### 2. es_str_false `graph=False want=False` 仍 FAIL（测试契约恒假式）

1. 用例契约：C 段 `("es_str_false", lit_ab, of_list("a"), False)` 与模块
   docstring（:54）都写明期望 False；判定行却是
   `if got is True and got == want:`——want=False 时**任何图输出都 FAIL**
   （got=False 被 `is True` 拦死，got=True 被 `== want` 拦死）。
2. 图判定正确：lead 复现原文 `[C es_str_false] graph=False want=False`；
   修复后该例 628 微步 PASS。
3. 真值锚：B 段同形输入 `deq_oflist_false`（`"ab"` vs
   `String.ofList ['a']`，真 env）lean 4.33.1 判 False，图一致 PASS(670)。
4. 内核依据：`try_string_lit_expansion_core`
   （`/home/xkq/lean4/src/kernel/type_checker.cpp:1145-1150`）命中臂返回
   `to_lbool(is_def_eq_core(whnf(string_lit_to_constructor(t)), s))`，可
   l_false；调用点 `if (r != l_undef) return r == l_true`（:1238-1239）
   ——true/false 皆终结 FINAL。期望 False 语义成立。
5. 修复：`got is want`（bool 恒等，既查值也查类型；异常字符串永非
   True/False 单例 → 严格性不降）。修恒假式 ≠ 放宽断言。
   C 段契约已同步 `docs/VM_SPEC.md` §14.8。

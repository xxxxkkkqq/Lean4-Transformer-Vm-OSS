# 007. WP6 图相位编号：单调追加、永不复用

- 状态：accepted（2026-09-15，WP6 收尾，代理 C3）
- 关系：延续 `lean_vm/build_vm.py` 既有帧相位约定（X = frame token 第 4 槽）；
  语义表在 `docs/VM_SPEC.md` §15。

## 背景

卡 006 设计期给 gcd 规划了 41-4e（十六段名）、给 shiftLeft 规划了 51-55。
实现落地时：gcd 实际占 41-53、56、57（借位减/比较/翻倍 pass 拆分与设计一
对多），shiftLeft 的 51-55 里 52/53/56/57 已被 gcd 吃掉，整段改号 61-68；
F1-F3/F9 尺寸守卫再用 71-76。若回头"按设计归位"重编号，diff 会污染三张
probe 证据链（trace_shl.py / trace_pow.py / trace_gcd* 的帧 X 读数）和全部
handoff 引用，且帧 X 是纯内部协议、无任何外部稳定性要求。

## 决策

1. 新相位一律取**当前已用最大号之后的未占用号**；已写入帧流的号永不回收
   复用，即使对应代码后来删除。
2. 设计文档（handoff 的规划段）与实现编号不一致时，**以实现为准**并在
   VM_SPEC 记实数；规划段原文保留作历史。
3. 相位号是图内部协议：不进 ENV 格式、不进二进制、不进 ENV 元数据，改名
   成本仅限 build_vm 注释与文档。

## 后果

- 现存号段：0-13（WHNF/infer/nat 基础+div/pow 循环）、21-33（bitop/shr）、
  41-53/56/57（gcd）、61-68（shiftLeft）、71-76（守卫，76=结果 strip
  扫描）。空洞 14-20、34-40、54-55、58-60、69-70 保留。
- 文档与代码注释必须写十进制号（帧 token 里也就是个整数），不许出现
  "4a" 之类混合进制名。
